Stack Technique

  • Langage: Python
  • Backend: Flask + Jinja2
  • Data: pandas, numpy
  • Visualisation web: Plotly (express + graph_objects)
  • Lecture Excel: xlrd via pandas.read_excel
  • Frontend: HTML, CSS, JavaScript (onglets + resize)
  • Exploration initiale: Jupyter Notebook
  • Environnement: venv + pip
  • Versioning: Git

Techniques Utilisées

  • Nettoyage et recodage des variables (SEX, EDUCATION, MARRIAGE, DEFAULT).
  • Feature engineering: n_months_late, avg_bill_amt, avg_pay_amt, repayment_ratio.
  • Analyse narrative en axes avec visualisations interactives.
  • Interface web responsive et orientée storytelling métier.

Difficultés Rencontrées

  • Interprétation métier des variables PAY_0 à PAY_6.
  • Harmonisation des catégories et comparabilité des indicateurs.
  • Gestion de la lisibilité avec beaucoup de graphiques.
  • Maintien des performances avec des graphiques interactifs.

Conclusion Générale

Le défaut ne survient pas d'un coup: il s'annonce par des retards récents, se renforce avec leur persistance, puis se confirme quand les remboursements ne suivent plus la facturation. Cette base analytique prépare directement la phase de modélisation.
