Interprétation

Si les deux courbes convergent rapidement et se stabilisent à une valeur élevée, le modèle n'est ni en sous-apprentissage ni en sur-apprentissage. Un écart persistant entre train et test indiquerait un sur-apprentissage à corriger (réduction de max_depth ou augmentation de min_samples_leaf).

Pistes d'amélioration

  • Optimisation des hyperparamètres (GridSearchCV / RandomizedSearchCV)
  • Seuil de décision personnalisé (ex. 0,35 pour maximiser le rappel)
  • SHAP values pour l'explicabilité individuelle
  • Gradient Boosting (XGBoost, LightGBM) en comparaison

Gestion du déséquilibre de classes

Le jeu de données présente ≈ 78 % de non-défauts contre ≈ 22 % de défauts. Sans correction, un classifieur naïf prédirait systématiquement "no default" en atteignant 78 % d'accuracy sans rien détecter.

class_weight="balanced" attribue à chaque classe un poids inversement proportionnel à sa fréquence :

w_k = n_total / (n_classes × n_k)

Classe 0 (78 %) → poids faible · Classe 1 (22 %) → poids élevé. Cela force le modèle à "pénaliser" davantage les erreurs sur les défauts.

Cohérence avec l'analyse DataViz

Les 3 axes explorés dans le Dashboard (profil client, historique de paiement, capacité de remboursement) se retrouvent directement dans le top des features importantes :

  • Axe 3 (remboursement) → repayment_ratio, avg_bill_amt confirment leur pouvoir prédictif
  • Axe 1 (profil) → LIMIT_BAL, AGE apportent un signal complémentaire
